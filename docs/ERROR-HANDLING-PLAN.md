## 2. Целевая модель ошибок

1. **Порт всегда возвращает значение.** `TextureSource`, `FilterSource` (и
   публичные методы реестров) возвращают `Effect<A, RenderError>`. Ни `null`, ни
   `undefined` как признак успеха.
2. **`throw` — только внутри синхронных модулей, которые не знают Effect**
   (`RenderState`, Pixi-таргет). Ровно одна граница превращает бросок в
   значение: `attemptForeign` внутри `applyCommand`.
3. **Defect — только ошибка разработчика** (битый манифест, вызов до
   инициализации). Он не попадает в счётчики виджета и не маскируется под
   `RenderFailed`.
4. **Absence отдельно от ошибки.** Если «ничего нет» — норма (например,
   незагруженный бандл), это `Option`/флаг, а не `Error`; если это промах по
   контракту — `AssetNotFound`.
5. **Ошибки одного набора живут в одном файле.** `RenderError` переезжает в
   `core/src/errors.ts`, чтобы `status.ts` не зависел от `apply-command.ts`.

Итог: у `applyCommand` остаётся два источника сбоя — значение из `E`-канала
портов и бросок из синхронного таргета, пойманный на одной границе. Третьего
пути нет.

## 3. Решения, требующие подтверждения

### 3.1. Судьба `NodeRegistry`

**Рекомендация: убрать как отдельный слой.** `RenderState` уже владеет индексом
узлов и сбором поддерева; `NodeRegistry` держит вторую `Map` и повторно собирает
то же поддерево. `has` и `remove` переезжают в `RenderTarget`, `removeNode`
возвращает удалённые `NodeId[]` (они нужны для освобождения фильтров). Контракт
`render-target.contract.ts` расширяется и гоняется на обеих реализациях.

Альтернатива: оставить `NodeRegistry` фасадом без собственной `Map`. Дешевле по
правкам, но слой не даёт поведения.

Цена: 2-3 часа, правки `ARCHITECTURE.md` §5.3 и §5.7.

### 3.2. Ошибка `AssetRegistry.init`

**Рекомендация: one-shot без внутреннего ретрая.** Сбой инициализации — это сбой
старта приложения, а не событие виджета: `Effect.die`, счётчики не растут.
Повтор — перезапуск приложения целиком. Удаляется сброс `initPromise` и обещание
«повтор возможен» из `ARCHITECTURE.md` §5.4.

Альтернатива: новый `AssetInitFailed` в каталоге ошибок, ретрай на уровне
активации. Дороже и требует решения, кто и сколько раз повторяет.

Цена: около 30 минут.

## 4. Фазы

Каждая фаза заканчивается `pnpm typecheck`, `pnpm lint`, `pnpm test` и
`goh comments --all`. Тесты пишутся до реализации и первые падают.

### Фаза 1. Политика и протокол (2 ч)

1. `docs/ARCHITECTURE.md` §6.1 — переписать в модель из §2: порты возвращают
   `Effect`, `throw` только у синхронных модулей, одна граница, defect только
   для ошибок разработчика. Убрать противоречие строк 369/376 и неверное
   утверждение, что наружу из кадра ошибка не летит.
2. `AGENTS.md` §4 (`effect-way`) — заменить формулировку про «бросок vs возврат
   значением» на новую, иначе следующая сессия будет писать по старой политике.
3. `docs/ROADMAP.md` — переписать итоги шагов 22-24 с пометкой «сделано иначе,
   чем в шаге N: …». Номера шагов не меняются.
4. `packages/protocol/src/commands.ts`, `events.ts` — вынести `Ready` и
   `Heartbeat` в `ServiceMessageSchema`; `WidgetToCore` принимает union команд и
   служебных сообщений. Провод не меняется, `PROTOCOL_VERSION` не растёт.
5. `packages/protocol/src/decode.ts` — `decodeWidgetToCore` на
   `Schema.decodeUnknownResult` плюс тесты. Заготовка для шага 25: сейчас декода
   на границе нет вообще.

Готово: документы описывают одну политику; схемы разделены; декодер есть и
покрыт тестом.

### Фаза 2. Порты и `applyCommand` (2 ч)

1. `apply-command.ts` — сигнатуры: `getTexture` →
   `Effect<Texture, AssetNotFound>`, `get` →
   `Effect<Filter, EffectNotFound | EffectCompileFailed>`, `setParam` →
   `Effect<void, EffectNotFound | InvalidEffectParam>`. `fromPort` удаляется,
   `applyLeaf` делает `yield*` напрямую.
2. `isRenderError` сужается до того, что реально бросает таргет:
   `UnknownNode | InvalidCommand`. Остальные ошибки приходят значением из
   `E`-канала; ручной реестр тегов больше не нужен.
3. Новый `packages/core/src/errors.ts` — union `RenderError`; `status.ts` и
   `apply-command.ts` импортируют его оттуда.
4. `packages/protocol/src/commands.ts` — `NodeKind`
   (`"container" | "sprite" | "text"`) вместо `string` в схеме, в `RenderTarget`
   и `RenderHandle`. `effectId` в `RenderTarget` — `EffectId`, не `string`.
5. Тесты: ошибка порта — значение, а не defect; пачка продолжается после сбоя;
   `Ready`/`Heartbeat` недостижимы в `applyCommand` по типу.

Готово: из `applyCommand` ушли `fromPort`, две мёртвые ветки и ручной guard.

### Фаза 3. Реестры (4 ч)

1. `asset-registry.ts` — API на `Effect`; `AssetBackend` остаётся Promise-
   границей и оборачивается `Effect.tryPromise`; `init` one-shot (решение 3.2).
2. `loadBundle` — in-flight `Map<bundleId, Promise>`; параллельные вызовы
   получают одну загрузку, `bundleLoaded` ставится только после успеха.
   `unloadBundle` ждёт in-flight, затем снимает бандл; ошибка —
   `BundleLoadFailed`.
3. `effect-registry.ts` — API на `Effect`; `register` заменяет карту определений
   целиком (сейчас эффект, удалённый из манифеста, остаётся жить).
4. `release(nodeId)` и `clear()` уничтожают фильтры через `Filter.destroy()`;
   вызывающий `release` определяется в фазе 4.
5. `testing/fake-asset-backend.ts` — управляемые обещания; тесты: два
   параллельных `loadBundle` дают одну загрузку, `unload` во время загрузки,
   типизированная ошибка `unload`, фильтры уничтожены.

Готово: гонок загрузки и утечки фильтров нет, все отказы типизированы.

### Фаза 4. Узлы, статус, очередь (3 ч)

1. Решение 3.1 в коде: `RenderTarget` получает `has`, `removeNode` возвращает
   удалённые id, контракт расширяется и проходит на обеих реализациях.
2. `applyCommand` после `RemoveNode`/`removeAll` передаёт id в
   `effects.release`; поддерево удаляется один раз, O(n²) уходит.
3. `status.ts` — `?? (() => performance.now())` плюс регрессионный тест без
   инжекта; `get` → `WidgetStatus | undefined`; `count` типизируется только
   не-ошибочными счётчиками, ошибки — через `recordError`; `flush(widgetId)`
   вместо уведомления на каждый инкремент.
4. `command-bus.ts` — `drain` не считает `processed`, добавляется
   `commit(widgetId, applied)`; пустой дренаж возвращает общий пустой массив без
   `splice`; конфиг валидируется при создании (обычный `Error`).
5. Тесты: `processed` не врёт при сбое; пустой кадр ничего не выделяет; `stats`
   после `commit`; дефолтный `now` не падает.

Готово: счётчики честные, панель не падает на удалённом виджете, пустой кадр не
аллоцирует.
